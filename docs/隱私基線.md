# WishTemple 隱私基線

最後盤點日期：2026-09-15

## 目前宣告

`WishTemple/Resources/PrivacyInfo.xcprivacy` 是 App target 的隱私 manifest。目前宣告：

- 不追蹤使用者，沒有 tracking domains。
- 不蒐集或傳送使用者資料至裝置外。
- App source 沒有直接使用 Required Reason API，因此 `NSPrivacyAccessedAPITypes` 為空。

願望雖然屬於使用者內容，但目前只透過 SwiftData 保存在本機，沒有傳到開發者或第三方伺服器。依 Apple 對「收集」的定義，目前不列入 `NSPrivacyCollectedDataTypes`。若未來加入同步、客服上傳、遠端分析或任何離開裝置的資料流，必須重新盤點。

## Required Reason API 盤點

盤點範圍是 distribution App target 的 `WishTemple/**/*.swift`，不把 unit-test target 的暫存檔案操作誤算為 App 行為。

| 類別 | 目前 App 直接使用 | Manifest 宣告 | 目前結論 |
|---|---:|---:|---|
| UserDefaults | 否 | 無 | 未實作設定儲存；加入時依實際用途選擇理由，app-only 用途可評估 `CA92.1` |
| File timestamp | 否 | 無 | SwiftData、JSON `Data` 與一般檔案操作本身不構成直接使用時間戳 API |
| System boot time | 否 | 無 | 無計時或開機時間 API |
| Disk space | 否 | 無 | 無磁碟容量 API |
| Active keyboards | 否 | 無 | 無讀取已啟用鍵盤列表 |

目前沒有第三方套件、第三方分析、廣告或當機回報 SDK。RealityKit、SwiftData、SwiftUI 與 Foundation 是 Apple framework，不是第三方 SDK。若加入套件或 binary dependency，合併前須檢查供應商的 privacy manifest、簽章要求、資料流與版本。

## 本機檢查

此檢查需要另外安裝 [ripgrep](https://github.com/BurntSushi/ripgrep)（指令名稱為 `rg`；它不是 Xcode 或 macOS 內建工具）。執行前可用 `command -v rg` 確認環境與 CI runner 已安裝；若找不到 `rg`，腳本會回傳失敗，避免略過 Required Reason API 掃描。

每次修改資料儲存、裝置資訊、分析、網路或 dependency 時執行：

```sh
./scripts/check_privacy_baseline.sh
```

腳本會驗證 plist 格式，並掃描 App Swift source 中五類 Required Reason API 的常見入口。它是快速防呆，不取代 Xcode／App Store 的 binary 分析；若掃描命中，需確認實際用途並在 manifest 填入 Apple 允許且相符的理由，不能只為了讓檢查通過而宣告。

## Release Archive 檢查

每個準備散布的 Release build 都應完成：

1. 執行 `./scripts/check_privacy_baseline.sh`。
2. 用 Xcode 執行 Product > Archive。
3. 在 Organizer 對 archive 執行 Generate Privacy Report，保存報告供該版本稽核。
4. 確認 archive 內含 `Products/Applications/WishTemple.app/PrivacyInfo.xcprivacy`。
5. 比對 App source、所有 dependency manifests、Xcode Privacy Report 與 App Store Connect 隱私標籤；任何差異都需有書面理由。
6. 檢查 Apple 最新的 Required Reason API 與指定第三方 SDK 清單，因規範可能更新。
