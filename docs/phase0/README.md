# Phase 0 Agent 快速驗證

狀態：**已完成，不阻擋 Phase 2A**

驗證版本：`phase0-agent-preflight-v2`

決策日期：2026-09-30

## 本輪目的

為避免前期招募、訪談與回訪讓核心開發無限期等待，Phase 0 改採 Agent-only 案頭驗證。Agent 以專案文件、公開來源、流程走查、風險紅隊與工程限制，先回答：

1. 不含擲筊的私人核心祈願流程，是否具備進入 UX／GUI 審查與 Phase 2A 開發的最低條件？
2. 哪些文化或安全風險無法由網路資料可靠消除，必須隔離於公開 MVP 之外？

本輪**不宣稱**已證明市場需求、真實完成率、留存、文化代表性或顧問認可。這些改為 Alpha／TestFlight 後的產品學習，不再是 Phase 2A 的前置阻擋。

## 決策

- **原型 A／核心祈願：通過 Agent 快速驗證。** 可立即進入正式 UX／GUI 審查與 Phase 2A 實作。
- **原型 B／擲筊：只允許內部原型。** 必須置於 feature flag、開發版或封閉展示環境，不納入公開 MVP、商店截圖、正式資料模型或使用者紀錄。
- **公開擲筊不是目前里程碑。** 日後若決定公開，再用本資料夾保留的訪談、原型測試與顧問審閱工具進行針對性驗證。
- 求籤、今日宜忌及其他會被理解為神意或決策指令的功能，不因本次 Agent 驗證自動取得開發或上線許可。

完整依據與限制記錄於[結果與決策](結果與決策.md)。

## Agent 驗證範圍

| 工作 | Phase 0 要求 | 結果 |
|---|---|---|
| 專案一致性檢查 | 願望保存、隱私、刪除與完成點不可互相矛盾 | 通過；A 版維持單一完成點 |
| 公開來源查證 | 優先採政府、文化機構與第一方規範 | 已完成初步來源矩陣 |

| 隱私檢查 | 核心資料本機保存，不要求真實宗教或敏感資訊 | 通過，可進工程實作 |
| 工程範圍檢查 | 未公開的擲筊不提前改 schema 或建立持久化 | 通過，B 保持原型隔離 |

## 不可變更的開發護欄

- 願望保存是核心流程唯一完成點。
- MVP 不需要擲筊、筊象或任何隨機結果才能完成願望。
- 不宣稱代表、認證或代辦任何實體宮廟。
- 不宣稱神明真實回覆、預測未來、保證祈福效果或提供決策指令。
- 願望內容預設只保存在裝置；不得進入分析、日誌或商店素材。
- 心中默念與文字輸入必須是等價路徑，不以敏感文字換取完整功能。
- 未通過未來公開驗證前，不把 B 版接入正式導覽、持久化、付費、廣告或通知。
