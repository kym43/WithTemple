# 未來真人驗證方案（非 Phase 2A 前置條件）

狀態：暫停，待核心 Alpha 或公開擲筊決策後再啟用。

本方案保留原 Phase 0 的真人研究方法，但不阻擋目前核心祈願開發。啟用時不得以 AI 模擬資料補足樣本，也不得把內部預試混入正式結果。

## 建議樣本

| 工作流 | 建議樣本 | 目的 |
|---|---:|---|
| 探索訪談 | 15–20 位成年潛在使用者 | 驗證私人祈願需求、使用情境、信任與文化界線 |
| 文化顧問審閱 | 3–5 位 | 審閱儀式措辭、筊象說明、數位揭露與停止規則 |
| A／B 原型測試 | 8–10 位 | 比較核心祈願與保存後可選擲筊 |
| 回訪 | 原型測試參與者，間隔 7–14 天 | 驗證回顧願望的實際需求及阻礙 |

使用者至少涵蓋經常、偶爾、很少／沒有宮廟或擲筊經驗三層，每層至少 3 人；不要只招募團隊親友或高度信仰者。

## 執行方式

1. 使用[招募篩選與邀請](招募篩選與邀請.md)招募，再以[使用者訪談與測試腳本](使用者訪談與測試腳本.md)執行。
2. 使用[顧問審閱表](顧問審閱表.md)取得文化與流程意見；重大爭議先處理再繼續測試。
3. 每位參與者都操作[原型 A](原型A-核心祈願.md)與[原型 B](原型B-保存後可選擲筊.md)，AB／BA 順序盡量各半。
4. 每完成一版立即在 `session-scorecard.csv` 新增一列，只用 `P001` 類匿名代碼。
5. 若修改關鍵文案或停止規則，提升研究版本並分開統計。
6. 依實際數據另建研究結果，不覆寫 Agent-only 的[結果與決策](結果與決策.md)。

## 計分欄位

| 欄位 | 允許值 |
|---|---|
| `participant_id` | `P001` 起的匿名代碼 |
| `session_date` | `YYYY-MM-DD` |
| `experience_segment` | `frequent`、`sometimes`、`rare` |
| `prototype_order` | `AB`、`BA` |
| `prototype_variant` | `A`、`B` |
| `assigned_result` | A 版為 `none`；B 版為 `sheng`、`xiao`、`yin` |
| 二元觀察欄 | `yes`、`no`；不適用為 `na` |
| `completion_seconds` | 從開始到看見「願望已保存」的整數秒數 |
| 評分欄 | `1`–`5`；拒答留白 |
| `notes` | 去識別化行為摘要，不放姓名、願望、求問或敏感逐字內容 |

## 建議指標與公開 B 門檻

- A 版願望保存完成率至少 80%。
- 真實宮廟代辦誤解率低於 10%。
- 至少 50% 目標使用者能提出具體真實試用情境。
- B 版完成率不得低於 A；小樣本只差 1 人時視為不確定。
- 超過半數 B 版受測者能在未提示下同時說明「願望已完成」及「結果只是數位文化體驗」。
- 停止提示後再次重擲率低於 10%。
- 權威／決策指令誤解率低於 5%。
- 因筊象延後醫療、安全、法律或財務必要行動的安全紅旗必須為 0。
- 顧問對名稱、結果說明、數位揭露與停止規則沒有未處理的拒絕或重大修改項目。

所有比率保留分子與分母；不得用偏好分數或「覺得有趣」取代理解與安全門檻。未達 B 門檻只代表 B 不公開，不影響 A 版核心。

## 資料管理

- 招募聯絡資料放在 repository 外，並與參與者代碼分開。
- 錄音、錄影或螢幕錄製逐次取得同意；拒絕錄製不影響參與。
- 計分表只記行為、勾選與去識別化摘要。
- 未另行取得同意時，原始影音在研究結論確認後 30 天刪除。
- AI 可協助主持、摘要及計算，但不得冒充受訪者、顧問或產生正式樣本。
